# AI Sports Precision Medicine

Сайт, кабинет специалиста и мобильный чек-ин спортсмена — ИИ-платформа медицинской персонализации спортсменов (Digital Athlete Twin) с моделями, обученными на открытых научных данных.

[![CI](https://github.com/Anuar-zxc/sportmed/actions/workflows/ci.yml/badge.svg)](https://github.com/Anuar-zxc/sportmed/actions/workflows/ci.yml)

**Сайт:** https://sportmed-eight.vercel.app · **Кабинет:** https://sportmed-eight.vercel.app/app

## Что внутри

| Путь | Содержание |
|---|---|
| `/` | Главная: браслет, что измеряет, кабинет, как работает, данные, роли, пилот, отличие от трекеров, безопасность, FAQ, заявка |
| `/investors` | Для партнёров и инвесторов: рынок, целевые показатели пилота, экономика |

### Функции кабинета

- **Обзор команды** — готовность, восстановление, риск, готовые к нагрузке; динамика за 7/30 дней с подсказкой; ранние сигналы; топ-5 по риску; рекомендации.
- **Спортсмены** — фильтры по статусу, поиск, сортировка по любой колонке, настройка колонок, добавление и удаление демо-профилей, карточка спортсмена.
- **Цифровой двойник** — профиль по 6 измерениям, прогноз готовности на завтра с интервалом и объяснением, факторы риска травмы, тренды HRV/сна/нагрузки, лабораторный срез, утренний чек-ин (обновляет прогноз).
- **Медицинские данные** — анализы и показатели устройств с референсами, динамикой и фильтром источника.
- **AI-аналитика** — orange flags, объяснение прогноза риска по факторам, динамика риска, **планировщик нагрузки** (что будет с риском при другом плане на 3 дня).
- **Как работает ИИ** — простыми словами: что умеют прогнозы, насколько им доверять и чего они не умеют; под раскрывашкой «для специалистов» — метрики против базовых линий, калибровка, важность признаков, источники и лицензии, **проверка на своих данных** (CSV, обработка только в браузере).
- **Рекомендации** — согласовать / отклонить / отменить, журнал решений, права по ролям.
- **Отчёты** — три CSV-отчёта для Excel (UTF-8, разделитель `;`).
- **Моя команда (режим пилота)** — local-first рабочее пространство для реальной команды: состав, утренние чек-ины, групповой ввод нагрузки (sRPE), импорт истории из CSV, прогнозы моделей на своих данных, резервные копии с шифрованием (PBKDF2 + AES-256-GCM) и восстановление на новом устройстве. Данные не покидают устройство.
- **Чек-ин по ссылке** — персональная ссылка и QR-код для каждого спортсмена; спортсмен отвечает с телефона за минуту без регистрации, ответ шифруется AES-256-GCM и возвращается специалисту ссылкой через мессенджер. «Входящие» принимают сразу всю переписку, дубликаты и подделки отклоняются, смена ключа отзывает все ссылки.
- **Журнал записей** — все данные спортсмена по дням с источником (спортсмен / кабинет / импорт / правка), исправление с проверкой диапазонов и удаление.
- **PDF-отчёт по спортсмену** — печатная версия цифрового двойника (светлая тема, без интерфейса).
- **Администрирование** (роль «Администратор») — в пилоте: сотрудники устройства и их роли, покрытие чек-инами, согласия спортсменов, ключ ссылок и резервные копии, журнал аудита (1000 событий, входит в резервную копию, экспорт в CSV). В демо — пользователи, приглашения и интеграции. Администратор не видит медицинские данные.
- **Настройки** — тема (тёмная/светлая/системная), компактный режим, роль, источники данных, матрица доступа, сброс демо-данных.
- **О платформе** и **Помощь** — стратегия, сравнение с референсами, экономика, FAQ, горячие клавиши.
- Глобально: поиск `Ctrl/⌘ K` и `/`, уведомления, выбор даты среза, смена роли (врач / тренер / психолог / администратор).

Роли определяют и меню, и содержание: врач видит всё, включая анализы; тренер — готовность, нагрузку и риск без анализов; психолог — самочувствие и сон без риска травмы, ACWR и аналитики; администратор — сотрудников, согласия и журнал без медицинских дашбордов. Недоступные роли разделы не показываются в меню, кнопка «Создать отчёт» есть только там, где есть данные для отчёта.

## Технологии

- Статический HTML, CSS и JavaScript без фреймворков и сборки. Графики — собственный SVG.
- `data.js` — детерминированная генерация вымышленных демо-данных (84 дня); индексы готовности/восстановления — прозрачные правила.
- `model.js` + `models.js` — инференс обученных моделей в браузере (деревья решений, линейная модель, калибровка, объяснения). Обучение и проверка — в [`ml/`](ml/README.md).
- Данные хранятся только в `localStorage` браузера (`asp_app_v1` — демо и настройки, `asp_pilot_v1` — реальная команда) и никуда не отправляются.
- `asp-crypto.js` — шифрование ссылок чек-ина на WebCrypto: ключ команды → HKDF-SHA256 → ключ спортсмена; ответы AES-256-GCM с привязкой к команде и спортсмену (AAD). Ключ живёт только в части ссылки после `#`, которая не передаётся на сервер.
- `sw.js` — service worker: кабинет и чек-ин открываются без сети, сайт устанавливается на телефон и компьютер.
- `vendor/qrcode.js` — генератор QR-кодов (MIT, kazuhikoarase/qrcode-generator).
- Оформление: молочно-белая светлая тема по умолчанию и яркий персиково-жёлтый акцент; тёмная тема — в тёплом графите (Настройки → Тема). Все цвета — токены в начале `styles.css`.
- Шрифты как на устройствах Apple: на Mac/iPhone/iPad — системный SF Pro (ничего не скачивается), на остальных — Inter (SIL OFL, `fonts/`, переменные оси толщины и оптического размера, 108 КБ на латиницу и кириллицу). Моноширинный — SF Mono / Menlo, запасной JetBrains Mono через `/gf/*`.
- Баннер cookie: «Необходимые» и «Аналитика» (Vercel Web Analytics, без cookie) — аналитика грузится только после согласия.
- Заголовки безопасности (CSP, HSTS и др.) и чистые адреса — в `vercel.json`.
- Доступность: WCAG 2.1 AA — контраст текста ≥ 4.5:1 в обеих темах, размер касания ≥ 44 px на сенсорных экранах, семантическая разметка и ориентиры, навигация с клавиатуры (в том числе по прокручиваемым таблицам), фокус в диалогах, `prefers-reduced-motion`. Проверяется автоматически axe-core в CI.
- SEO: structured data schema.org (Organization, WebSite, SoftwareApplication, FAQPage; на юридических страницах — WebPage и BreadcrumbList), Open Graph, canonical, sitemap.

## Деплой

Репозиторий подключён к Vercel: каждый push в `main` публикуется автоматически (Framework Preset — Other, без сборки).

Локально: `python tests/server.py 8765` и откройте `http://127.0.0.1:8765` — сервер повторяет чистые адреса и заголовки (CSP) из `vercel.json`. Шрифты локально не загрузятся — они проксируются Vercel.

## Тесты

На каждый push и pull request GitHub Actions ([`ci.yml`](.github/workflows/ci.yml)) проверяет:

1. синтаксис всех скриптов и JSON-файлов;
2. `ml/verify_js.py` — признаки и прогнозы моделей в браузере совпадают с Python до 1e-14;
3. `tests/e2e.py` — сквозные сценарии в Chromium с CSP как в продакшене: лендинг и юридические страницы, все разделы демо-кабинета, меню и обзор по ролям, шифрование, полный цикл чек-ина по ссылке (выдача, ответ с телефона, приём, дубликат, подделка, пачка из переписки, смена ключа), журнал, зашифрованная копия и восстановление на «новом устройстве», сотрудники и аудит, печать, офлайн, отсутствие горизонтальной прокрутки на телефоне. Любая ошибка JS, нарушение CSP или ответ 4xx/5xx валит тест;
4. `tests/a11y.py` — доступность по WCAG 2.1 AA движком axe-core: 17 страниц сайта и кабинета в светлой и тёмной теме, на десктопе и телефоне. Любое нарушение уровня serious/critical валит сборку (контраст 4.5:1, имена кнопок, семантика списков и таблиц, ориентиры страницы).

```bash
pip install -r ml/requirements.txt playwright && python -m playwright install chromium
python ml/verify_js.py
python tests/e2e.py          # или: python tests/e2e.py pilot
python tests/a11y.py         # доступность (axe-core скачивается в ~/.cache один раз)
```

## Что обновлять

- **Оператор персональных данных и контакты** — в юридических страницах, `index.html`, `main.js` (`CONFIG.email`) и `app.js` (`EMAIL`). Когда появится ТОО/ИП, добавьте наименование, БИН и адрес.
- **Домен** — `canonical`, `og:url`, `robots.txt`, `sitemap.xml`.
- **Документы** версионируются: при изменении обновите номер редакции и дату.

> Юридические тексты подготовлены на основе законодательства Республики Казахстан о персональных данных и здравоохранении. Перед пилотом их рекомендуется согласовать с юристом.
